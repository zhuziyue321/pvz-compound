# 新手教程（冒险模式 1-1 / 1-2 / 1-5）

原版 1-1 / 1-2 都是教程关：**第一波僵尸都在玩家种下第一株植物之后才出现**，提示文本按原版顺序逐条弹出。

- **1-1**：只有中间 1 行草皮但**仍是 5 行地图**（`map_front_1row`，其余 4 行是不可种植的无草皮土行）、
  开局 150 阳光、只有豌豆射手可用，教捡卡 → 种植 → 收阳光 → 再种一棵。
  **教程写在 `run_flow()` 里**（一句话一个 await，见下文「两种教程跑法」），排在**允许操作之后、开战之前**：
  玩家先在一个没有僵尸的草坪上把三件事学会，流程走到「开战」才出第一波。
  已经通关过 1-1 的那次进入**不播教程**，改播「准备…安放…植物」红字（`prefab.ready_set_plant()`），
  顺序退化成普通关的 `预览 → 选卡 → 移回视角 → 允许操作 → 准备安放植物 → 开战`。
  教程敢指定「豌豆射手」的前提见该关卡脚本的文件头注释：首次打 1-1 的玩家只有这一张卡。
- **1-2**：只有中间 3 行草皮（`map_front_5row`）、拥有豌豆射手 + 向日葵，教种满三棵向日葵
  （种下第一棵向日葵后开始倒计时刷新僵尸）。
- **1-5**：**铲子教学关**（`card_mode = 2` 传送带 + `is_bowling_stripe` 保龄球关），同时也是**开场教程关**。
  开局草坪上预置 3 株豌豆射手（`all_pre_plant_data`，`plant_cell_pos` 为 1 开始的 (行,列)，
  按原版摆在 **(2,6) / (3,8) / (4,7)** —— 三株都在红线右侧，铲掉之后那几列本来就种不了），
  教 **拿铲子 → 铲掉一株 → 铲光草坪**；
  整段教程跑在**关卡正式开局之前**（`is_opening_tutorial = true`），原版顺序是：
  **戴夫开场白 → 玩家铲光草坪 → 戴夫介绍保龄球（说到「我们去玩保龄球！」的同时红线出现）→ 预览僵尸 → 开始关卡**。
  教程**只有 4 步、以戴夫惊喜对话收尾**，原版 1-5 没有「干得漂亮」这一句提示 —— 戴夫说完就直接进关卡。
  因为开场被教程占掉了，1-5 自己把 `first_wave_delay` 调到 `6.0`，传送带与第一波僵尸都由
  「开始关卡」的通用流程启动（传送带：开局刷新卡槽时；第一波：`ZombieManager.start_game()`）。


本项目把这一整套做成**数据驱动**的教程：推进逻辑在 `TutorialManager`
（`src/managers/tutorial_manager.gd`），步骤数据在**关卡脚本里现场构造**。

## 数据与开关

- **教程数据有两个来路**（`ResourceLevelData.get_tutorial_data()` 统一取值）：
  - 关卡字段 `tutorial_data`（老 `.tres` 关卡 / 没改过的关卡脚本）：不为空 = 本关是教程关；
    1-1 / 1-2 / 1-5 的数据原在 `res://data/tutorial/`，已内联进关卡文件。
  - **关卡脚本在 `run_flow()` 里现场构造**（推荐，现在的 1-1 / 1-2 / 1-5 都这样）：
    `await prefab.tutorial(_build_tutorial())`，数据在同文件的 `_build_tutorial()` 里 new。
    此时字段为空，脚本要**覆写 `has_tutorial() -> true`** 声明「本关有教程」，
    `init_tutorial_manager()` 才会在流程开始前建好管理器（数据随后由教程事件补交，
    见 `MainGameManager.setup_tutorial_manager`）。
- `ResourceTutorialData.steps` 是 `Array[ResourceTutorialStep]`，每步 = 一句提示文本 + 一个完成条件
  （`E_FinishType`：不操作等 N 秒 / 捡起卡片 / 种下 N 株指定植物 / 收一次阳光 / 阳光达到 N /
  **拿起铲子** / **铲掉 N 株植物** / **铲光草坪**）
  + 可选箭头目标（`E_PointerTarget`：卡片 / 草坪 / 阳光 / **铲子** / **草坪上的植物**）
  + 可选附加动作（`dave_dialog` 进入本步时先播一段戴夫对话、`spawn_sun` 立刻掉一颗阳光、
    `start_zombie_wave` 启动第一波僵尸、`start_conveyor_belt` 启动传送带）。
- 提示文本**一律用原版 advice 字符串**，出处是 `data/strings/lawn_strings.txt` 的 `ADVICE_*` 条目
  （如 `ADVICE_CLICK_SEED_PACKET` = 点击种子包，把它捡起来！），不要另写文案。
- `only_first_playthrough`（默认 true）：该关已有通关记录就不再播教程 —— 对齐原版「教程只在冒险模式第一轮出现」。

  判定读 `curr_all_level_state_data[save_game_name].IsSuccess`，不单独落库。
- `is_opening_tutorial`（默认 false）：**整段教程在关卡正式开局之前跑完**。
  为 true 时时间轴的「开场教程」事件排在「戴夫对话」之后、`预览僵尸 / 选卡` 之前，`await` 教程跑完；
  为 false（1-1 / 1-2）时教程照旧在 `main_game_start()` 进入 `MAIN_GAME` 之后跑。
  1-5 是唯一用它的关卡：铲草坪必须发生在预览僵尸之前。

## 两种教程跑法

`TutorialManager` 同时支持两种跑法，**用「有没有 tutorial_data.steps」区分**（`has_steps()`）：

| 跑法 | 数据形态 | 谁推进 | 现有关卡 |
|------|---------|-------|---------|
| **自驱 steps** | `ResourceTutorialData.steps` 一串步骤 | `start_tutorial()` 自己从头跑到尾 | 1-2、1-5 |
| **逐步事件** | 没有 steps | 关卡流程 `run_flow()` 里的一个个 `await prefab.xxx()` | **1-1** |

**为什么 1-1 改成逐步事件**：教程本身就是一串「说什么 → 等玩家做什么」的句子，
把它写成数据 step 之后，「这一关到底教了什么」要翻两个地方（关卡脚本的 `_build_tutorial()` + `TutorialStep` 资源字段）。
改写成 `run_flow()` 里的 await 之后，一个函数从上往下读就是教程全文，
而且中途要插一句台词、调一次箭头顺序，改的都是这一处，不用再去动步骤资源。

逐步模式事件（都在 `LevelPrefabs` 上有对应的一行式调用，参数即事件脚本上那几个字段）：

| 预制体 | 事件脚本 | 做什么 |
|--------|---------|-------|
| `allow_operation()` | `LevelTimelineEventTutorialAllowOperation` | **放开玩家的手**：推进到 `MAIN_GAME` + 放出出战卡槽 + 收回预览僵尸；**不出怪、不天降阳光** |
| `advice(文本)` | `LevelTimelineEventTutorialAdvice` | 显示提示台词；**传空串 = 收起提示条与箭头** |
| `point_card(植物)` / `point_lawn(植物)` / `point_sun()` / `hide_pointer()` | `LevelTimelineEventTutorialPointer` | 箭头指到种子包 / 草地 / 阳光；`hide_pointer()` 收起 |
| `spawn_sun()` | `LevelTimelineEventTutorialSpawnSun` | 掉一颗阳光下来（不是关卡的天降阳光定时器，那个仍由「开战」启动） |
| `wait_take_card(植物)` | `LevelTimelineEventTutorialWaitTakeCard` | 等玩家把这张卡捡到手上 |
| `wait_plant(数量, 植物)` | `LevelTimelineEventTutorialWaitPlant` | 等玩家种下植物（`timeout` 留 0 = 一直等） |
| `wait_plant_timeout(数量, 植物, 秒)` | 同上（`timeout` > 0） | **限时**等：时限内种下返回 `true`，到点还没动手返回 `false` |
| `wait_collect_sun()` | `LevelTimelineEventTutorialWaitCollectSun` | 等玩家点掉一颗阳光 |
| `wait_sun_enough(数值)` | `LevelTimelineEventTutorialWaitSunEnough` | 等阳光攒够（进入时已经够就立刻往下走） |
| `end_tutorial()` | `LevelTimelineEventTutorialEnd` | **收尾**：提示条 queue_free、停 per-frame 判定、退订事件 |

四件事要注意：

1. **第一个教程事件会自动把 TutorialManager 拉进逐步模式**
   （`MainGameManager.ensure_tutorial_stepped_mode()`，没有管理器就现建），
   所以关卡脚本要照旧覆写 `has_tutorial() -> true`；
   「已通关就不播」由 `run_flow()` 自己 `if not _mg.is_curr_level_success()` 判断，
   这时还要**覆写 `should_run_tutorial() -> true`** —— 否则已通关的存档进关时管理器压根不会建，事件全部空转。
2. **`end_tutorial()` 不能漏**：提示条挂在 `CanvasLayerUI` 上，不摘掉会一直压在草坪上；
   `TutorialManager` 的 `_process` 也会继续每帧解析箭头目标。
3. **教程要靠玩家动手，得先 `allow_operation()`**：「能不能点卡片 / 种植」的判据是
   `main_game_progress == MAIN_GAME`（`Card._on_button_pressed`、`HandManager._on_main_game_progress_update`），
   `allow_operation()` 就是把阶段推进到 `MAIN_GAME`。
   出怪 / 天降阳光 / 生成墓碑仍然在 `main_game_start()` 里，由「开战」事件触发 —— 两者必须分开。
4. **逐步模式不再替关卡开第一波**：自驱 steps 有个 `start_zombie_wave` 附加动作，逐步模式没有；
   教程跑完紧接着就是 `await prefab.start_battle()`，第一波由 `ZombieManager.start_game()` 正常启动。
   因此「教程期间还没开波」这条 `zombie_manager.start_game()` 里的 `is_tutorial_running()` 抑制分支
   对逐步模式**用不上**（教程在它之前就跑完了）。
5. **「超时才补提示」用 `wait_plant_timeout()`**：有些提示不该立刻说，得先给玩家自己试的机会。
   原版 1-1 说完「阳光够了」就是**直接等**，只有玩家 4 秒不动手才补那句「点击豌豆射手，再种一棵！」——
   写成 `if not await prefab.wait_plant_timeout(...): await prefab.advice(...)` 即可。
   它内部轮询 `_plant_done_num`（种植次数只在信号回调里累加，不在完成条件的查询表里，
   所以不能用 `_is_step_condition_satisfied()` 判断）。
6. **玩家中途退回主菜单：协程照跑，但主游戏已经没了**。教程协程挂在「等玩家 XX」上时，
   一旦 `MainGameManager` 被释放，signal / timer 会把协程唤醒，接下来的 `prefab.xxx()`
   传的就是个已释放对象（GDScript：`.. argument 1 (previously freed) is not a subclass of ..`）。
   闸门在 `LevelPrefabs._run()`：主游戏失效就直接返回，后面每个 await 快速跳过、协程自然收尾。
   同理 `TutorialManager` 里凡是要摸 `main_game` 的地方都用 `is_instance_valid()` ——
   **`main_game != null` 对已释放对象是 `true`**，照样崩。

## 运行期三个模块

| 模块 | 职责 |
|------|------|
| `TutorialManager`（`src/managers/tutorial_manager.gd`） | 顺序推进步骤 / 逐步模式的文本与等待判定、生成阳光、启动第一波僵尸、收尾 |
| `TutorialAdviceUI`（`src/ui/tutorial_advice_ui.gd` + `src/ui/tutorial_advice_ui.tscn`） | **屏幕下方的提示条** + 指向箭头，挂在主游戏 `CanvasLayerUI`（层 50）下 |
| `TutorialPointer`（`src/ui/tutorial_pointer.gd`） | 箭头绘制：直接画五边形（不依赖美术素材），箭尖落在目标点、箭尾朝向提示条 |

**提示条的形态（2026-10-03 起）**：教程不再用「草坪上飘着的小黑框」，一律改**贴屏幕底部的通栏提示条**
（左右各留 24、距底 20，高度按文本行数撑开、最小 64）。位置由 tscn 的 Bottom Wide 锚点决定，
**没有 `set_advice_position()` 这类外部定位接口**，`ResourceTutorialData.advice_box_position` 随之删除。
改样式去改 tscn；改高度请先看下面第 1 条坑。

> **提示 UI 上踩过的三个坑**（改动这个 UI 前先看一眼，症状都很隐晦）：
>
> 1. **Label 没拿到布局宽度时宽度是 1px，不是 0**。Godot 会把 Control 的 size 钳到不小于
>    `minimum_size`，而 Label 的 minimum_size 是按可用宽度折行算的 —— 拿 1px 去算，
>    一句 12 字的提示能算出 **5008** 高的黑框。
>    所以宽度按面板算（`advice_panel.size.x - 左右 content_margin`），并且
>    `_ready()` 里先把宽度钉上、`Label.resized` 时再按实际行数重定一次高度。
> 2. **`TutorialAdviceUI._process()` 是「一次性提示」（第一次掉金币）专用的**，
>    它会 `_update_once_pointer()`，而 `_once_target` 为 null 时就 `hide_pointer()`。
>    步骤教程那条路每帧由 `TutorialManager` 喂 `update_pointer`，两者叠加 = **每帧把刚点亮的箭头按回去**，
>    表现出来就是「第一句提示没有箭头」。现在该函数只在 `_once_target` 有效时干活，
>    目标消失后收一次箭头并 `set_process(false)`。
>    顺带：`TutorialPointer._ready()` 里的 `visible = false` 曾晚于同一帧的 `point_to()` 执行
>    （节点 instantiate 后当帧就被指目标），同样会把箭头按没 —— 已改成看 `_has_target` 决定。
> 3. **锚点布局下别直接写 `size.y` / `position`**。提示条用 Bottom Wide 锚点（`anchor_top/bottom = 1.0`），
>    高度由 `offset_bottom - offset_top` 决定，写 `size.y` 会在下一次布局被 offsets 覆盖回去，
>    表现出来的症状是「多行长提示被裁掉」；改用 `offset_top = offset_bottom - 高度` 才是「贴底往上长」。
>    同理 `get_advice_box_center()`（箭头箭尾）不能拿 `position + size * 0.5` 算 ——
>    锚点模式下 `position` 落在锚点上，必须走 `get_global_transform_with_canvas()`。

改教程前必须知道的八件事：

1. **创建与启动时机**：`MainGameManager._ready()` 在 `init_manager()` 之后调 `init_tutorial_manager()`
   （节点挂在 `Manager/TutorialManager`，无教程数据 / 已通关时不创建）。启动有两处：
   - 普通教程（1-1 / 1-2）：`main_game_start()` 进入 `MAIN_GAME` 后调 `start_tutorial()`；
   - **开场教程**（`is_opening_tutorial = true`，1-5）：时间轴的「开场教程」事件（排在戴夫对话之后）
     `await start_tutorial()`，跑完才继续「预览僵尸 → 开始关卡」。
   开场教程跑在 `CHOOSE_CARD` 阶段，而铲子界面默认只在 `MAIN_GAME` 显示，所以 `start_tutorial()`
   会主动刷一次手持物界面（`hand_manager.refresh_all_hand_ui()`）；判定能不能用铲子统一走
   `MainGameManager.is_lawn_playable()`（主游戏阶段 **或** 开场教程运行中）。
2. **第一波僵尸归教程管**：`ZombieManager.start_game()` 一旦发现 `main_game.is_tutorial_running()` 为真就**不开波**，
   改由步骤里的 `start_zombie_wave` 触发；教程收尾时会兜底补开一次，避免教程异常导致永远不出僵尸。
   开场教程（1-5）跑完时关卡还没开局，`start_zombie_wave` / `start_conveyor_belt` 都不要写在步骤里，
   交给开局流程按 `first_wave_delay` 开波，否则僵尸会在「预览僵尸」的时候就上场。
3. **完成条件走事件 / 信号**：捡卡听 `EventBus "hand_card_take"`、种植物听每个 `PlantCell.signal_plant_create`、
   收阳光听 `EventBus "add_sun_value"`。唯一按帧判定的条件是「阳光 ≥ N」（在 `_process` 里读
   `CardSlotBattle.sun_value`）—— `add_sun_value` 的订阅回调顺序不保证卡槽已经加过数值，不能在里面直接读。
4. **指向草坪时指向「真能种下的格子」**：地图是数据驱动的（1-1 只有一行铺了草皮 `map_front_1row.tres`、
   1-2 / 1-3 只有中间三行 `map_front_5row.tres`），所以从草坪中心向外找第一个 `judge_is_can_plant()` 为真的格子，
   找不到才退回几何中心。保龄球关（1-5 / 小游戏）：**红线右边一律不可种植**（`WallnutBowlingStripe`
   把那些格子置成 `IsNoPlantBowling`），靠种植条件过滤后箭头只会落在红线左边。
5. **提示条不拦输入**：UI 根节点、提示条、箭头全部 `mouse_filter = IGNORE`，否则会吃掉草坪点击。
6. **只播一次的两道闸**：`is_finished` 保证多轮游戏不重播；`only_first_playthrough` 保证已通关的关卡不重播。
7. **取卡片一律走 `TutorialManager._get_curr_card_list()`**：普通关取出战卡槽 `card_slot_battle`，
   **传送带关（1-5 / x-10）没有出战卡槽**，卡片在 `card_slot_conveyor_belt.curr_cards` 里；
   直接读 `card_slot_battle` 在传送带关拿到的是 null，箭头会消失。同理 `SunValueAtLeast` 这类读阳光的步骤
   只对普通卡槽关卡有意义（传送带关卡片免费、不掉阳光）。
8. **教程能接管传送带与第一波僵尸的启动时机**：`CardManager.card_slot_update_main_game()` 发现本关
   有教程管理器**且教程还没跑完**（`not tutorial_manager.is_finished`）就**不自己启动传送带**，改由步骤的
   `start_conveyor_belt` 触发；`_stop_tutorial()` 里也兜底补一次，避免教程异常中断后永远没有卡片。
   **判定用「有没有教程管理器 + 跑完没有」而不是「教程是否在跑」** —— 卡槽刷新发生在
   `start_tutorial()` 之前（用 `is_tutorial_running()` 会漏判），而开场教程（1-5）在开局前就已经跑完
   （这时必须让关卡通流程自己启动传送带，否则一直没卡）。
   铲子教学还有一道保险：本关拿不到铲子（关卡禁了铲子 / 玩家还没通关 1-4）时 `start_tutorial()`
   直接收尾，不会卡在「点击拾取铲子」那一步把传送带一起堵死。
9. **戴夫对话也能挂在步骤上**：步骤的 `dave_dialog` 不为空时，进入该步先播完这段对话再显示提示
   （原版 1-5：铲光草坪后戴夫才介绍保龄球）。`advice_text` 留空的纯对话步骤不会弹空气泡；
   1-5 的最后一步就是这种纯对话步骤，播完即收尾，**后面不再跟「干得漂亮」这类收尾提示**。

## 戴夫对话（关卡开场 / 教程步骤）

戴夫有三个挂载点，文案一律取自 `data/strings/lawn_strings.txt` 的 `CRAZY_DAVE_*` 条目：

| 时机 | 落位 | 现有关卡 |
|------|------|---------|
| 关卡开场（选卡之前） | **关卡脚本 `run_flow()` 里现场构造并传参**：`await prefab.dave_dialog(_build_dave_dialog())`；老关卡才是字段 `ResourceLevelData.crazy_dave_dialog` | 1-5（2400~2406：自我介绍 + 让玩家用铲子清理草坪）；**2-1（201~207：进入夜晚场景的开场白）**；**3-1（501~505：进入泳池场景的开场白）**；**4-1（801~803：进入浓雾场景的开场白）**；**5-1（1201~1204：进入屋顶场景的开场白）**；**5-5（1301~1311：禅境花园收尾 + 警告飞贼僵尸）** —— 台词都内联在各关卡脚本的 `_build_dave_dialog()` 里 |
| 教程某一步之前 | 教程步骤 `ResourceTutorialStep.dave_dialog` | 1-5 第 4 步（2410~2415：保龄球惊喜，在 `_build_tutorial()` 里构造） |
| 多轮关卡第 2 / 3 批（摆下一批罐子之前） | **同上，按批各一个方法**：`await prefab.dave_dialog(_build_dave_dialog_2())` | **4-5 → 第 2 批（2700~2704：再给你一批花瓶）、第 3 批（2800~2802：最后一批）** |

- 播放统一走 `MainGameManager.play_crazy_dave_dialog()`：戴夫挂在 `CanvasLayerUI`，说完自动离场。
- 取值两条路：`prefab.dave_dialog(对话)` **传进来的优先**；没传才走
  `ResourceLevelData.get_crazy_dave_dialog_on_round(轮次)`（老 `.tres` 关卡：
  第 1 轮 `crazy_dave_dialog`，第 2 轮起 `crazy_dave_dialog_next_round[轮次 - 2]`，没有则不播）。
  每句话一个 `CrazyDaveDialogDetailResource`。
- 关卡脚本不给 `crazy_dave_dialog` 字段赋值时，要**覆写 `has_dave_dialog() -> true`** 做声明
  （有对话就不播戴夫推销，见 `is_dave_sell_possible` / `DaveSellManager.is_can_sell`）。
- **某一句可以顺带触发一个事件**：`CrazyDaveDialogDetailResource.on_talk_event` 填事件名时，
  戴夫念到这一句的同一时刻 `EventBus.push_event(...)`（原版 1-5：`surprise_001`「我们去玩保龄球！」
  配 `on_talk_event = show_bowling_stripe`，保龄球红线订阅该事件后画出来，
  事件名常量 `WallnutBowlingStripe.SHOW_STRIPE_EVENT`）。
- 台词里的 `{PLAYER_NAME}` 由 `CrazyDave._resolve_text_placeholder()` 换成当前用户名
  （`Global.user_manager.curr_user_name`），取不到用户名时叫「我的邻居」。
- **跳过规则**（`MainGameManager.is_skip_level_dave_dialog()`）：
  - 教程关（1-5）：跟着教程的 `only_first_playthrough` 走，已通关导致没创建教程管理器时，开场对话一起跳过；
  - 非教程关（2-1 / 3-1 / 4-1 / 5-1）：关卡资源的 `dave_dialog_only_first_playthrough` 为真时，本关已有通关记录就不再播
    （对齐原版「进入夜晚 / 泳池 / 浓雾 / 屋顶的开场白只在第一次进该场景说一次」）；该开关默认 false，即每次进关都会播。
  - **5-5 是两段口径拼在一起的一段对话**：原版前 3 句（1301~1303，禅境花园收尾）只在第一轮说，
    后 8 句（1304~1311，警告飞贼僵尸）每轮都说；而 `dave_dialog_only_first_playthrough` 是**整段级**开关，
    做不到「前半段跳过、后半段照播」。本仓库按「每轮都播」处理（开关保持默认 false），
    代价是重玩 5-5 时前 3 句会多说一遍 —— 要精确对齐原版得给 `CrazyDaveDialogDetailResource`
    加逐句的「只说一次」标记并在 `CrazyDave.start_dialog()` 里过滤，目前没做。
  - **与花园解锁口径的冲突（待定）**：`ConstUnlockLevel.GARDEN_UNLOCK_ADVENTURE_LEVEL = 45` 表示
    通关 5-5 才拿到禅境花园，而原版 5-5 的 1301~1303 是「拿到花园之后」的收尾话；
    不想让戴夫在花园解锁前提前提花园的话，删掉 `dialog_detail/adventure_05_05/opening_000~002.tres`
    并从 `adventure_05_05_opening.tres` 里去掉这三句即可。
- **台词里的原版动画标签要剥掉**：`lawn_strings.txt` 的句尾常带 `{MOUTH_BIG_SMILE}` / `{MOUTH_SMALL_SMILE}` /
  `{SHAKE}` / `{SHOW_XXX}` 这类标签，本仓库的气泡是纯文本，这些标签一律**不写进 `text`**
  （例：4-1 的 `CRAZY_DAVE_802` 落库为「因为我曾停留在雾中并突然跳出来，吓呆了一大群人！」）；
  只有带 `{SCREAM}` / `{SCREAM2}` 的疯言疯语句才额外把 `is_crazy` 设为 true
  （例：1-5 的 `opening_006`「开始挖吧！」）。
- 本关有戴夫对话（`has_dave_dialog()`：字段非空，或关卡脚本覆写返回 true）时，
  戴夫推销（`DaveSellManager`）让位给关卡对话。
  推销最早在 2-2 触发（`ConstUnlockLevel.DAVE_SELL_ADVENTURE_LEVEL`），所以 2-1 配对话不会顶掉推销；
  **3-1 配了对话之后，商店解锁（通关 3-4）前的最后一档推销窗口就没了** —— 玩家到 3-1 才攒够 750 金币时，
  该档卡槽扩充要等商店解锁后自己去买（推销条件与让位逻辑见 `DaveSellManager.is_can_sell()`）。

### 给别的关卡加一段开场戴夫对话

1. 在关卡脚本里加一个 `func _build_dave_dialog() -> CrazyDaveDialogResource:`，
   按现有关卡的写法在里面 new 每一句（`CrazyDaveDialogDetailResource`，文本抄 `lawn_strings.txt`
   的对应 `CRAZY_DAVE_*` 条目，占位符 `{PLAYER_NAME}` 保持原样），最后 `assign` 成
   `CrazyDaveDialogResource` 并 `return`（不用再建 `dialog/*.tres`、`dialog_detail/*` 那些文件）。
2. `run_flow()` 里写 `await prefab.dave_dialog(_build_dave_dialog())`（放在「预览僵尸 / 选卡」之前）。
3. 覆写 `func has_dave_dialog() -> bool: return true`；要「已通关就不再播」就把
   `dave_dialog_only_first_playthrough` 设为 true（这个开关仍在 `_init()` 里）。
4. **打开游戏**进该关卡过一遍（对话只有打开游戏才看得见），见 [验证流程.md](../验证流程.md)。

多轮关卡要给**第 2 轮起**也配对话时，按批各建一个方法（`_build_dave_dialog_2()` …），
在 `run_flow()` 里按批传（4-5 就是三批三个方法），不必动代码 —— 播的时机由流程自己排。

## 给别的关卡加教程

**先选跑法**：教的东西是一串固定的「说一句 → 等玩家做一件事」，且**要排在开战之前**（1-1 那样）→ 用逐步事件；
要挂在自驱流程里（1-2 / 1-5 那样，或需要 `start_zombie_wave` / `start_conveyor_belt` 这类附加动作）→ 用自驱 steps。

### 逐步事件（1-1 的写法）

1. `run_flow()` 里按要教的顺序把预制体排下来：
   `allow_operation()` → `point_card(植物)` → `advice(台词)` → `wait_xxx()` → …… → `advice("")` → `end_tutorial()`。
   要「已通关就不播」就用 `if not _mg.is_curr_level_success(): await _tutorial_flow()` 包起来。
2. 覆写 `func has_tutorial() -> bool: return true` **与** `func should_run_tutorial(_mg) -> bool: return true`
   （后者保证 TutorialManager 一定被创建，理由见上文「两种教程跑法」的第 1 条）。
3. 玩家要动手，第一个教程事件之前必须有 `await prefab.allow_operation()`。

### 自驱 steps（1-2 / 1-5 的写法）

1. 照 1-2 / 1-5 的写法，在关卡脚本里加 `func _build_tutorial() -> ResourceTutorialData:`
   （里面 new 每个 `ResourceTutorialStep` 并 `assign` 成 `ResourceTutorialData` 返回），
   改提示文本与完成条件。
2. `run_flow()` 里写 `await prefab.tutorial(_build_tutorial())`；
   覆写 `func has_tutorial() -> bool: return true`；
   若本关需要「开局就够种植物」的阳光，同时按原版改 `start_sun` 等字段。
3. 若本关需要「开局就够种植物」的阳光，同时按原版改 `start_sun` 等字段。

### 两种写法共同的最后一步：打开游戏验证

跑 `powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Windowed -Scenario probe_tutorial`
（1-1）、`-Scenario probe_tutorial_1_2`（1-2）或 `-Scenario probe_tutorial_1_5`（1-5）——
探针覆盖教程全流程 + 原版提示顺序 + 第一波僵尸的启动时机 + 已通关不再播。
**必须带 `-Windowed`**：提示条与箭头只有打开游戏才看得见，无头跑批证明不了行为对不对
（见 [验证流程.md](../验证流程.md)）。
逐步模式的探针不看步骤下标（没有下标），推进判据是**提示文本**（`TutorialManager.get_advice_text()`），
提示顺序由探针订阅 `signal_advice_changed` 逐句记录。

## 第一次掉落钱的一次性提示（冒险模式 2-1 起）

金钱在冒险模式 2-1 才解锁（`ConstUnlockLevel.MONEY_UNLOCK_ADVENTURE_LEVEL`）：判定是
「当前正在打的关卡序号 >= 2-1」（`get_max_success_adventure_level() + 1`），也就是**通关 1-10 后进入 2-1 就开始掉钱**，
不用等通关 2-1。**第一次掉出金币时**
草坪上弹一次「存钱来买更酷的道具吧！」（原版 `ADVICE_CLICKED_ON_COIN`），箭头指向掉出来的那枚金币，
5 秒后自动消失。这不是教程关步骤，是**全局只弹一次**的一次性提示：

| 环节 | 位置 |
|------|------|
| 触发 | `DIM_Coin.create_coin()` 生成金币后推 `EventBus "first_coin_drop"`（携带那枚 `Coin`） |
| 显示 | `MainGameManager._on_first_coin_drop()`：实例化 `SceneRegistry.TUTORIAL_ADVICE` 挂到 `CanvasLayerUI`，调 `TutorialAdviceUI.show_advice_once()`（箭头每帧跟随金币，金币被捡走就收起箭头） |
| 只弹一次 | `GlobalGameState.is_first_coin_advice_shown`，弹完立刻 `SaveService.save_now()` 落存档，旧档读不到该字段按 `false` 处理 |

花园场景也有 `DIM_Coin`，但没有 `MainGameManager` 订阅该事件，所以**只在战斗关卡里弹**。
自动回归：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_first_coin_advice`
（输出 `[FIRSTCOIN] result=`），实机确认时用 `-Windowed` 看提示条与箭头。
