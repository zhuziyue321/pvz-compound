## 目标

把 `minigame_08_zombie_aquarium.gd` 从「借了个泳池普通关卡当占位」改成原版《怪怪水族馆》那套养僵尸玩法：
点鱼缸造脑子喂潜水僵尸 → 僵尸定时产阳光 → 攒 1000 阳光买奖杯通关；僵尸 20 秒没吃到脑子饿死，全死光判负。

## 步骤

1. **先查原版数值，再写常量**（照 [AI查wiki避坑.md](../参考存档/AI查wiki避坑.md) 的分级与来源注释）：
   仓库里 `data/strings/lawn_strings.txt` 居然已经有 `[ZOMBIQUARIUM_*]` / `[ADVICE_ZOMBIQUARIUM_*]` 原版文案（A 级来源，
   比 wiki 更硬），wiki.gg 的 `Zombiquarium` 页 + 灰机wiki 交叉验证了「开局 50 阳光 / 2 只潜水僵尸 / 脑子 5 阳光 /
   缸里最多 3 个脑子 / 僵尸 100 阳光一只 / 20 秒饿死 / 1000 阳光买奖杯」。数值一律进 `src/core/consts/const_zombiquarium.gd`。
2. **摸清关卡生命周期**：`LevelScriptBase.run_flow()` 是顺序协程；本关不走 `prefab.show_zombie / choose_card / start_battle`，
   改成 `await mg.main_game_start()`（推进到 MAIN_GAME + 相机归位）后 `await aquarium.signal_finished`。
3. **宠物僵尸复用潜水僵尸场景**：按**展示态**初始化 `E_CharacterInitType.IsShow`（`ready_show()` 会关掉受击框 / 攻击 / 移动组件、
   血量条也不显示），再用 `anim_component.stop_anim()` 关掉动画树、直接用 `AnimationPlayer` 播
   `zombie_snorkle.tscn` 里已经躺着的 `Zombie_snorkle_aquarium_swim / _bite / _death`。
4. **新建 `src/zombiquarium/`**：`zombiquarium_manager`（总控 + UI）/ `zombiquarium_pet`（宠物）/ `zombiquarium_brain`（下沉的脑子），
   三个场景登记进 `SceneRegistry`；关卡脚本只当驱动壳。
5. **写探针** `test/scenarios/probe_zombiquarium.gd`：两条线（通关线 / 判负线），22 条断言。
6. ~~想用 Area2D 接点击~~ → 改用 `_unhandled_input` + `get_local_mouse_position()`：省掉碰撞形状，
   而且 Control（按钮）会先吃掉点击，天然不会「点按钮同时造脑子」。

## 关键决策与理由

- **宠物不新做角色、复用 `Z012Snorkle`** —— 水族馆那三条动画（`zombie_snorkel_aquarium_swim/bite/death`）本来就在
  潜水僵尸场景的 AnimationPlayer 里，重做一套身体贴图既没有素材也违反「角色走注册表」。用展示态初始化即可当木偶用。
- **水族馆挂世界空间（Node2D），不挂 CanvasLayer** —— 产出的阳光进 `mg.suns`（世界节点，`z_index = 4002`）。
  挂 CanvasLayer 会把阳光盖住看不见也点不到；所以水族馆 `z_index = 4000`、`position = camera_2d.position`。
- **阳光走主游戏那一份（`CardSlotBattle.sun_value`）** —— 收阳光的表现、点击、存档全部现成，本关只负责花。
- **通关仍走 `EventBus.push_event("create_trophy", ...)`** —— 与「打完最后一波」同一条结算线，奖杯抛出来玩家点了才通关。

## 踩坑

1. **藏 UI 时把阳光条一起藏没了** —— `main_game_start()` 会把出战卡槽 `reparent` 到 `CardSlotContainer`，
   直接 `card_slot_container.visible = false` 连阳光计数一起消失。
   → **正解**：只藏卡片位（`CardUiList`）与铲子 / 手套（遍历容器子节点，跳过出战卡槽）。
2. **前景层盖住水族馆** —— `CanvasLayerFG/Frontground` 在 CanvasLayer（layer 5）上，世界节点再高 `z_index` 也压不过。
   → **正解**：进关时单独 `visible = false`。
3. **本关没人推进到 MAIN_GAME** —— 本关不走 `start_battle`，而 `main_game_start()` 只在开战流程里被调。
   → **正解**：`run_flow()` 里自己 `await mg.main_game_start()`（它内部有「相机兜底归位」，跳过选卡直接开战的入口就是它）。
4. **跑 `run_autopilot.ps1` 读到的输出是别人的** —— 并发有另一个 agent 也在跑 autopilot，
   而这个脚本的输出落在**共享**的 `$env:TEMP\pvz_autopilot\ap_out.txt`，后跑的进程会把前一个的输出覆盖，
   表现是「我传的是 `probe_zombiquarium`，报告里却写着 `probe_beghouled`」。
   → **正解**：多人 / 多 agent 并行时，直接调引擎并把输出重定向到自己的文件，且必须用
   `cmd.exe /c "... > out.txt 2> err.txt"`（Godot 的 Windows exe 是 GUI 子系统，只有 cmd 重定向才拿得到 stdout）。
5. ~~`godot --check-only --script` 能查语法~~ → **不成立**：这条路径不注册 autoload，`Log` 直接报
   `Identifier not found`，误报一大片；要查就跑真场景（autopilot）。

## 人工验证方法（无头跑不出画面，这一关需要开窗口看一眼）

1. 主菜单 → 迷你游戏 → 第 8 关「僵尸水族馆」。
2. 开局：整屏是一口鱼缸（不是草坪），左上角阳光显示 **50**，缸里有 **2 只潜水僵尸在游**（游动动画在播）。
3. 点鱼缸水域：掉一个脑子、阳光 −5；僵尸会游过去咬掉（脑子被吃掉后饥饿清零）。
4. 连点 4 次：缸里最多同时 3 个脑子，第 4 次被拒（不扣阳光）。
5. 等一会儿：僵尸身上冒阳光，点了才进账（+25）。
6. 阳光 ≥ 100 时「购买潜水僵尸」可点；≥ 1000 时「购买奖杯」可点 —— 点了抛奖杯，再点奖杯通关。
7. 放着不喂：僵尸身体发绿黄（饿死前报警），20 秒后饿死；两只都死光 → 红字「僵尸吃掉了你的脑子」并进入失败流程
   （原版文案是「你的宠物僵尸已经全部死亡了！」，仓库缺这张图，暂用红字顶）。
